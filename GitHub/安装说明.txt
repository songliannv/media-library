【v3.8.0 升级说明】

  本版为线上 Fatal 修复：max_execution_time 变量在 MySQL 5.7 不兼容。

  ★ 触发原因
    v3.7.9 上线后 MySQL 5.7 用户报：
    PDOException: SQLSTATE[HY000] [1193]
    Unknown system variable 'max_execution_time'
    根因：MYSQL_ATTR_INIT_COMMAND 硬编码了 max_execution_time=10000，
    但 max_execution_time 是 MariaDB 10.1.1+ / MySQL 8.0.16+ 才支持的
    变量，MySQL 5.7 完全不认识。

  ★ 修复内容
    core/DB.php 改为「两阶段连接」动态探测：
      阶段 1：用「仅 SET NAMES」的极简连接建立探测通道；
      阶段 2：SHOW VARIABLES LIKE 'max_execution_time' 检查变量是否存在，
              存在才把 max_execution_time=10000 加进最终 init_command。
    探测失败（权限不足/网络异常）时 catch 静默降级，不影响核心功能。

  ★ 兼容范围
    MySQL 5.7 / MySQL 8.0+ / MariaDB 全线版本均可运行。

  ★ 性能影响
    仅在建连时多一次 TCP + 一次 SHOW VARIABLES（约 0.1-1ms）。
    PHP-FPM 每 worker 只建一次连接，摊销到万次请求里几乎为 0。

  ★ 部署要点
    - **无需执行 SQL**（无表结构变更）。
    - **无需改配置**（PDO 调优项行为不变，仅在扩展未定义时降级跳过）。
    - 覆盖即生效。建议重启 PHP-FPM 让 persistent 连接立即生效；
      否则下次请求自动加载新代码。
    - 前台强刷 + 后台强刷即可。

  ★ 兼容性
    完全兼容 v3.7.9 及以前版本。PHP 8.2+ 唯一基线。

【v3.7.9 升级说明】

  本版为线上 Fatal 修复：MySQL 扩展专属常量兼容。

  ★ 触发原因
    v3.7.8 上线后部分环境报 Fatal error:
    Undefined constant PDO::ATTR_STATEMENT_CACHE_ENABLED。
    根因：ATTR_STATEMENT_CACHE_ENABLED / MYSQL_ATTR_INIT_COMMAND /
    ATTR_STATEMENT_CACHE_MAX 均为 pdo_mysql 扩展专属常量，在部分 PHP
    编译选项或驱动切换场景下未定义，直接引用导致致命错误。

  ★ 修复内容
    core/DB.php 全部 MySQL 扩展专属常量改用 defined() 保护，
    常量缺失时静默跳过对应调优项，不再致命。核心 PDO 通用常量
    （ATTR_ERRMODE / ATTR_DEFAULT_FETCH_MODE / ATTR_EMULATE_PREPARES /
    ATTR_TIMEOUT）保持直接引用。

  ★ 部署要点
    - **无需执行 SQL**（无表结构变更）。
    - **无需改配置**（PDO 调优项行为不变，仅在扩展未定义时降级跳过）。
    - 覆盖即生效。建议重启 PHP-FPM 让 persistent 连接立即生效；
      否则下次请求自动加载新代码。
    - 前台强刷 + 后台强刷即可。

  ★ 兼容性
    完全兼容 v3.7.8 及以前版本。PHP 8.2+ 唯一基线。

一、服务器要求
----------------------------------------------------------------
  · 面板：宝塔 Linux 面板
  · PHP：8.2 及以上（推荐 8.3/8.4）
  · 数据库：MySQL 5.7+ 或 MariaDB 10.4+
  · 扩展：pdo_mysql、curl、openssl、mbstring（宝塔默认都有）
  · 伪静态：必须配置（见第四步）

二、上传文件
----------------------------------------------------------------
  1) 宝塔 → 网站 → 添加站点
     填你的域名；一并创建数据库，记住「数据库名 / 用户名 / 密码」。

  2) 宝塔 → 文件 → 进入站点根目录（一般是 /www/wwwroot/你的域名/）。

  3) 把本包内【全部文件】上传到站点根目录。
     注意是把包里的文件夹和文件直接放进去，不要再套一层目录。
     传完后站点根应该能看到 index.php、install.php、admin、core、api 等。

  4) 权限：目录 755、文件 644（宝塔默认即可）。

三、设置运行目录与 PHP 版本
----------------------------------------------------------------
  · 宝塔 → 网站 → 设置 → 网站目录 → 运行目录保持为「/」（根目录）。
  · 同一页面的「PHP 版本」选 **8.2 或更高**（推荐 8.3）。
  · 若开了「防跨站攻击(open_basedir)」，保持默认即可；若后续自检报权限
    FAIL，可在同一位置临时关闭再复查。

四、配置伪静态  ★必做
----------------------------------------------------------------
  不配这一条，后台 /admin、接口 /api/v1/*、资源请求 /request 等
  动态地址会全部 404（但首页仍能打开，容易误判成「没装好」）。

  宝塔 → 网站 → 设置 → 伪静态 → 下拉选「自定义」，把下面整段粘进去并保存：

      location / {
          try_files $uri $uri/ /index.php?$query_string;
      }
      location ^~ /config/   { return 404; }
      location ^~ /sql/      { return 404; }
      location ^~ /core/     { return 404; }
      location ^~ /cron/     { return 404; }
      location ^~ /adapters/ { return 404; }
      location ^~ /tools/    { return 404; }
      location ~* \.(sql|md|lock|bak|ini|log|env|sh|yml|yaml|conf|sample)$ { return 404; }
      location ~* ^/(setup|upgrade|update) { return 404; }

  说明：
  · 第一条是核心：把动态地址交给 index.php 处理；真实存在的静态文件
    和静态内页（/uisc/xxx.html）仍由 Nginx 直接返回，不消耗 PHP。
  · 后面几条是安全保护，防止别人下载你的配置、源码、SQL 与备份文件。
  · 目录保护必须写「^~」，写成普通 location /config/ 会被面板自带的
    .php 正则抢先命中，等于没保护。
  · 安装路径这条【故意不写 install】：网页安装器 install.php 由它自身判定
    （已安装就返回 404），若在 Nginx 层拦死，未安装时就永远装不了了。
  · 不要套用面板里 ThinkPHP / Laravel 的预设伪静态，本项目不是那些框架。

五、安装（网页 / 命令行，二选一）
----------------------------------------------------------------

  【方式一】网页安装（推荐，不用终端）

   1) 浏览器打开：  http://你的域名/install.php
      （也可以先打开首页 http://你的域名/ ，点页面上的
        「🚀 开始网页安装」按钮进入）

   2) 页面会先做环境自检（PHP 版本、扩展、目录权限），
      不通过的项目标红，并直接给出修法。

   3) 填表：数据库地址 / 端口 / 库名 / 用户名 / 密码，
      管理员账号 + 密码（登录后台用，就是你自己的账号），
      站点名称与网址。

   4) 点「开始安装」→ 自动建表 → 生成 config/config.php →
      写入安装锁。成功页会告诉你管理员账号 / 后台地址 / 自检地址。

   5) 装完再打开 /install.php 就是 404 了 —— 这是【正确现象】：
      安装器已自动锁死，任何人都无法借它重装你的站。

  【方式二】命令行安装（适合重装 / 迁移 / 没有 web 环境）

   宝塔 → 网站 → 设置 → 终端（或用自己的 SSH 工具连服务器），执行：

       cd /www/wwwroot/你的域名
       php tools/install-cli.php

   按提示依次输入：数据库地址（一般 127.0.0.1）、端口、库名、用户名、
   数据库密码，以及【管理员账号 + 密码】（登录后台用）。

   程序会自动完成：检测环境 → 连接数据库 → 建表 → 生成
   config/config.php → 写入安装锁。

  · 两份安装器是【同一套内核】，用哪个装上来的结果都一样。
  · 重装 / 换服务器：命令行加 --force（原 config.php 会自动备份）；
    网页重装则先删掉 config/install.lock 与 config/config.php。
  · 安装信息备忘写在 config/install-info.txt（里面有管理员账号，不含密码），
    该目录公网访问不到，但记下后仍建议删掉它。

十、计划任务速查（宝塔面板「计划任务」页添加）
----------------------------------------------------------------
  每一条都是独立的 Shell 脚本任务；添加步骤（每条都一样）：

     宝塔面板 →「计划任务」→「添加任务」
       · 任务类型：Shell 脚本
       · 任务名称：（见下面每条建议名称）
       · 执行周期：按下面「周期」栏选择
       · 脚本内容：把下面「命令」一栏整段粘贴到「脚本内容」框里

  注意：命令里的 php 建议写绝对路径（如 /www/server/php/82/bin/php），
        否则某些面板环境 PATH 找不到 php 命令，任务会静默失败。
        宝塔默认的 /usr/bin/php 在多数站点也是指向正确版本的，可用 `which php` 查一下。

  ─────────────────────────────────────────────────────────────
  任务 ①：每小时采集（必配，保持站点持续更新）
  ─────────────────────────────────────────────────────────────
    任务名称：媒资库-每小时采集
    执行周期：N 小时 → 1 小时（或选「每小时」）
    脚本内容：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/sync_hourly.php --quiet

    作用：按各源官方限制取「今日最热 / 最多人看」，已入库的条目跳过；
          自带三重保护（最小间隔 55 分钟跳过、进程锁、请求上限 8 次），
          就算误配多条也不会重复烧上游配额。

  ─────────────────────────────────────────────────────────────
  任务 ②：每日热门全量同步（推荐每天一次）
  ─────────────────────────────────────────────────────────────
    任务名称：媒资库-每日热门同步
    执行周期：1 天 → 每天 03:30（凌晨低峰）
    脚本内容：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/sync_trending.php --quiet

    作用：本周窗口 + 每源 40 条 + 末尾全量重建静态页，把整站对齐一次；
          与「每小时采集」走同一引擎、同一份参数（后台改的参数，两者都生效）。

  ─────────────────────────────────────────────────────────────
  任务 ③：每日过期条目刷新（可选）
  ─────────────────────────────────────────────────────────────
    任务名称：媒资库-每日刷新
    执行周期：1 天 → 每天 05:00
    脚本内容：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/sync_refresh.php

    作用：把超过 cache.stale_days（默认 30 天）的老条目重新拉一次 TMDB 详情，
          保持评分 / 热度 / 简介的新鲜度；每次最多处理 200 条，不会压垮上游。

  ─────────────────────────────────────────────────────────────
  任务 ④：每日重建静态页（可选，与「每日同步」二选一）
  ─────────────────────────────────────────────────────────────
    任务名称：媒资库-每日重建静态页
    执行周期：1 天 → 每天 04:00
    脚本内容：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/build_static.php

    作用：把全站的 HTML 内页 / 静态页重写一次，用于「改了分类 / 改了下拉选项 /
          想整体刷新缓存」的场景。平时不需要，条目有变动时后台会自动重建那一条。

  ─────────────────────────────────────────────────────────────
  任务 ⑤：定时链接失效检测（v3.2.3 新增，推荐必配）
  ─────────────────────────────────────────────────────────────
    任务名称：媒资库-链接失效检测
    执行周期：按你的更新频率选：
      · 内容频繁更新 / 网盘账号活跃 → N 小时 → 6 小时
      · 常规使用                   → 1 天 → 每天 04:30
    脚本内容：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/link_check.php --quiet

    作用：逐个检测所有已匹配条目的网盘链接是否还有效（走夸克 / 百度 / 阿里 /
          迅雷 / 光鸭 / UC 六家的官方匿名分享接口，见 v3.2.2 说明）。
    参数（可选，加在命令末尾）：
      --limit=40      单次最多检测多少个条目（默认 40，上限 200）
      --budget=20     单次运行的秒数上限（默认 20 秒，避免计划任务超时）
      --stale=360     距上次检测超过多少分钟才复检（默认 360=6 小时；0=每次都检）
      --pan=xunlei    只检指定网盘（逗号分隔，如 --pan=xunlei,quark；省略=全部）
      --dry           只读不写库（排错用）
      --quiet         只输出一行结果（推荐在计划任务里加）

    推荐命令（每 6 小时批量检测，超时秒数放宽到 60 秒）：
      /www/server/php/82/bin/php /www/wwwroot/你的域名/cron/link_check.php --limit=40 --budget=60 --quiet

    查看结果：后台「条目匹配 → 已匹配」子页，每行状态徽章会显示「✓ 有效 X/Y」
              或「✗ 失效 X/Y」，鼠标悬停可看到上次检测时间；失效原因（如
              「分享已失效」「提取码错误」）落在 link_checks.msg 列，
              点「检测」按钮可查看单条详情。

  ─────────────────────────────────────────────────────────────
  常用命令速查（想手动跑也可以直接进宝塔终端粘贴）
  ─────────────────────────────────────────────────────────────
    php /www/wwwroot/你的域名/cron/sync_hourly.php --help   看全部参数
    php /www/wwwroot/你的域名/cron/sync_hourly.php --dry    只探测不入库（排错）
    php /www/wwwroot/你的域名/cron/sync_hourly.php --force  忽略「最小间隔」强跑
    php /www/wwwroot/你的域名/cron/sync_hourly.php --quiet  只输出一行，适合计划任务日志

    退出码：0 = 成功（含「因最小间隔跳过」）；1 = 失败。
            在宝塔「计划任务 → 日志」里能直接看出每条任务上次执行的结果。

  补充：
  · 用网址访问 cron/*.php 会返回 404（脚本只允许命令行执行，防被远程触发）；
  · 所有采集参数（每源条数 / 时间窗口 / 排序 / 数据源开关 / 最小间隔）都在
    后台「同步采集 → 采集参数」里改，改完保存即时生效，无需重启；
  · 想彻底关掉自动采集，直接把上面的计划任务删除即可，代码里没有隐藏开关。

八、常见问题速查
----------------------------------------------------------------
  Q：打开 /admin 或 /api/v1/* 是 404？
  A：伪静态没配好，回到第四步。检查是否保存成功、是否粘成了别的规则。

  Q：打开 /request 是 404？
  A：同样是伪静态；另外确认站点根目录没有被占用的同名文件或目录。

  Q：访问 /install.php 是 404，是不是装不了？
  A：分两种情况。
     ① 站点【已经装好】了 → 404 是正常的，安装器已自动锁死
        （config/install.lock 存在即对所有人返回 404），与文件不存在
        完全一样；确实要重装就先删掉 config/install.lock 与
        config/config.php。
     ② 站点根目录里【没有】install.php（用的是旧包，或上传时漏了）
        → 从发布包把它传到站点根目录即可，或直接走第五步的命令行安装。

  Q：命令行跑完了，首页还是「站点尚未安装」？
  A：① 确认站点根存在 config/config.php；
     ② 打开看里面 db 段的密码是否还是 CHANGE_ME 占位值；
     ③ 用 check.php 看第 3 组「安装状态」的具体原因。

  Q：登录后一会儿又变回未登录？
  A：PHP 会话目录不可写。宝塔 → 软件商店 → PHP-x.x → 设置 → 配置修改，
     把 session.save_path 指向的目录建好并给 www 用户可写权限。

  Q：界面样式乱了 / 改的设置前台没变化？
  A：先强制刷新（Ctrl+F5）；仍不行就宝塔「清空网站缓存」并重启 PHP。

  Q：https:// 打开是 502 Bad Gateway，http:// 却正常？
  A：说明 Nginx 的 443 那段里 PHP 转发坏了（80 段是好的，所以页面出得来）。
     ① 宝塔 → 网站 → 该站点 → 配置文件：看 listen 443 段里的
        include enable-php-XX.conf; 在不在、版本与「PHP 版本」是否一致；
     ② 宝塔 → 软件商店 → 对应 PHP 版本 → 重启；
     ③ 仍不行看 /www/wwwlogs/你的域名.error.log 最后几行，
        Nginx 会直接写明原因（如 connect() to unix:...sock failed）；
     ④ 也可以把「网站 → 设置 → PHP 版本」重选一次并保存，
        让面板重写站点配置。

  Q：升级新版本会覆盖我填的设置吗？
  A：不会。后台改的设置都存在数据库里，且发布包不含 config/config.php。
     升级方法：先备份 → 覆盖上传新包 → 重启 PHP → 强刷页面 →
     打开 check.php 体检。

九、发布保护说明
----------------------------------------------------------------
  本版要求 PHP 8.2+。发布目录中的 PHP 文件是 AST 混淆版，不是 ionCube/SourceGuardian 编码加密版。Nuitka 只能处理 Python，不能用于本项目 PHP。
  如需真正编码保护，请使用支持 PHP 8.2 的 ionCube Encoder + ionCube Loader，或 SourceGuardian + 对应 Loader。编码器在构建机运行，宝塔服务器同时为 PHP-FPM 和 CLI 安装匹配 Loader；否则网页能打开但计划任务可能报“未安装 Loader”。
  当前工作区没有商业编码器授权文件，因此不能把本版称为“加密发布包”。
