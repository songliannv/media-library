## 升级步骤

1. **先备份**：把站点目录整体留一份（至少备份 `config/config.php` 与数据库）。
2. 把本包内文件按相同路径**覆盖上传**到站点根目录，保持目录结构不变。
3. 清理 opcache 或重启一次 PHP（宝塔 → 软件商店 → PHP → 重启）。
4. 前台与后台都强刷一次（`Ctrl+F5`，手机端清一下缓存）。
5. 打开 `check.php`，看 **第 11 组「注册与资源请求」** 是否全部通过；
   再打开 `/request` 与 `/user/register` 确认两个新页面能正常打开。

## 不需要做的事

- ❌ **不需要手工执行任何 SQL** —— 两张新表 `app_users` / `app_requests` 会在首次访问时**自动创建**，
  并且**缺列自愈**（已存在缺列会自动 `ALTER TABLE ... ADD COLUMN`）。
  仅当数据库账号**没有建表权限**时，才需要手工导入兜底脚本 `sql/migrate_users.sql`。
- ❌ 不需要重新安装，也不需要改伪静态规则。
- ❌ 不会影响已保存的后台设置（设置存在数据库 `app_settings` 表，不在文件里）。

## 本次改了什么

**前台 · 注册 / 登录 / 退出（新增）**
- 新增 `/user/register`、`/user/login`、`/user/logout` 三个页面；用户名 2~20 位（支持中文），
  密码 6~64 位并**不能与用户名相同**，可选邮箱，另带**算术验证码**。
- 密码用 `password_hash()` **加盐存储**；登录若账号不存在也照跑一次假散列校验，**不泄露账号是否存在**。
- 风控：同一 IP 每小时最多注册 3 个；登录失败满 5 次锁 15 分钟；隐藏蜜罐字段；验证码一次有效、30 分钟过期。

**前台 · 独立页「资源请求」（新增，路径 `/request`）**
- 结构：状态统计条 → 公告 → 提交区 → 我的请求 → 大家都在找 → 分页。
- 提交内容：资源名称（必填）· 类型（6 大分类）· 年份 · 补充说明 · 联系方式（默认带账号邮箱）。
- **必须登录才能提交**（可在后台关）；输入片名会提示站内是否已收录同名条目。
- 「我的请求」只看自己的，未处理的可以自己撤回。

**前台 · 顶栏与导航**
- 顶栏右上角新增用户区：未登录显示「登录 / 注册」，已登录显示「我的请求 / 用户名 / 退出」（手机端隐藏用户名）。
- 顶部导航新增「资源请求」入口（可在后台关掉）。

**后台 · 新增一级页签「资源请求」**
- **请求列表**：统计条 + 搜索 + 状态筛选 + 分页；每条可标记已找到 / 回复 / 关闭 / 重开 / 删除。
- **注册用户**：通过审核 / 禁用 / 解禁 / 重置密码 / 删除；**删用户只停用并保留其历史请求**。

**后台 · 站点设置新增「资源请求」二级页（13 项）**
- 开关：开放注册 · 必须登录才能提交 · 注册后需审核 · 算术验证码 · 允许游客查看列表 · 公开「大家都在找」 ·
  显示联系方式字段 · 顶部导航显示入口。
- 限制：每人每天最多提交条数（0 = 不限） · 资源名称最少字数。
- 文案：页面标题 · 页面简介 · 站长公告。

**数据层**
- 新增两张表 `app_users`（账号 / 邮箱 / 密码散列 / 状态 / 失败次数 / 锁定时间 / 注册 IP 与时间）与
  `app_requests`（用户 ID / 标题 / 类型 / 年份 / 备注 / 联系方式 / 状态 / 站长回复 / 关联条目 / IP / 时间）；
  **首次访问自动创建 + 缺列自愈**，覆盖升级不用手工导 SQL。

**自检**
- `check.php` 新增 **第 11 组「注册与资源请求」**（现共 **11 组**）：开关 / 登录要求 / 风控摘要 / 可见性与文案 /
  两张表与缺列 / 用户与请求数量 / `password_hash` 可用性 / **会话目录可写性** / 代码与路由是否就位，
  并**真实探测** `/user/register` 与 `/request` 的 HTTP 状态。

**预览页**
- `preview/` 新增 `register.html`、`request.html`、`user-admin.html`，预览台 `responsive.html` 已加入这三页。
  （预览页不随发布包发布，属于源码目录里的开发辅助文件）

## 回滚方法

把备份的对应文件覆盖回来即可。**注意**：本次新增了两张数据表，回滚代码后这两张表会闲置（不影响原有功能）；
如需彻底清理，手工执行 `DROP TABLE app_users; DROP TABLE app_requests;`（会丢失已注册用户与请求记录，请谨慎）。
