# 媒资资料库 media-library-api · 增量升级包

**v1.6.3 → v1.6.4**　｜　2026-09-23　｜　4 个变化文件（修改 4 / 新增 0 / 删除 0）

## 这次修的是什么（一句话）

**站点一装好，访问首页就 500 —— `Fatal error: Class 'Config' not found`。**

`home.php` 是**全局命名空间**文件，却用了短类名 `Config::sub(...)` 而没有 `use Core\Config;`，
PHP 于是在全局命名空间里找一个并不存在的 `Config` 类，直接致命错误。
本版补上 `use Core\Config;` 与 `core/Site.php` 的显式 require —— **零行为变化、数据库无变更**。

> 该问题 v1.6.0 引入（加「最新更新」区块时从 `core/Views.php` 抄代码，漏了命名空间差异），
> v1.6.0 ~ v1.6.3 的用户只要**站点已安装**就会踩到；之所以此前没暴露，是因为站点一直没装成、
> 首页走的是「站点尚未安装」引导页，`home.php` 从未被执行。

## 升级步骤

1. 备份：至少备份站点根的 `config/config.php` 与数据库。
2. 把本包内的文件按**相同路径覆盖上传**到站点根目录（保持目录结构不变）。
3. 清理 opcache，或重启一次 PHP（宝塔 → 软件商店 → PHP → 重启）。
4. 前台强刷一次（Ctrl+F5；手机端清一下缓存）。

## 不需要做的事

- **不需要执行任何 SQL**：本次无表结构变更、无新表。
- 不需要重新安装，不需要动 `config/config.php`。
- 不影响已保存的后台设置（设置存在数据库 `app_settings` 表）。
- 不需要改伪静态（与 v1.6.3 的伪静态建议无关，那条是给**未安装**站点用的）。

## 回滚方法

把备份的 `home.php` 覆盖回去即可（会回到 v1.6.3「首页 500」的状态）。
`index.php` / 两份说明书只是版本号，回不回滚都不影响运行。

## 小提示

- 升级后确认站点根的 `home.php` 大小约 **2121 字节**（v1.6.3 是 1788 字节），
  文件头部能看到 `use Core\Config;` 这一行。
- 顺手做一次体检：`check.php?token=你的后台令牌`。
- 这次新增了一项发布前静态检查 `phpclassscan.py`（类名解析扫描）——
  `phpcheck`（括号）与 `php56scan`（PHP 7.0+ 语法）**都查不出**这类命名空间问题，
  以后每版都会先扫一遍再发包。
