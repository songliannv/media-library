接口配置（PanSou 网盘搜索）

对接 PanSou 聚合搜索服务，采集到资源后自动搜索并写入网盘下载地址。

启用 PanSou 接口

PanSou 是开源的网盘资源搜索服务（聚合 TG 频道与网盘插件）。启用后，采集到资源可自动去搜网盘链接并写入下载地址。

部署方式

本机部署一般填 http://localhost:8888 或 http://127.0.0.1:8888，不必走公网。

接口地址

PanSou 服务根地址，不要带 /api/search。例：http://localhost:8888

连通正常（频道 42 个）（插件 18 个）· HTTP 200 · 耗时 86 ms

账号 / 密码（仅服务端开启鉴权时才需要）

默认部署无需填写。

线路展示名

只是给你自己在后台看的备注名，例：PanSou 主线路。

启用哪些网盘类型

决定搜索结果里保留哪些网盘。只勾你站点真正会展示的几种，能显著减少无用的补地址请求。

采集后自动补网盘下载地址

同步 / 采集入库新条目后，自动用标题去 PanSou 搜索，把命中的网盘链接写进该条目的下载地址。

自动补地址的写入策略

搜到的结果未必就是同一部作品（同名不同版本很常见）。默认「仅高度匹配才自动写入」，其余进待确认队列，避免写入错误链接。

标题匹配最低相似度

越高越严格。建议 75~85：既不会漏掉「片名+年份」这类正常差异，又能挡掉同名不同版本。

每条资源最多写入几个网盘链接

每种网盘取最优的一条。建议 3~5，页面更清爽。

补地址时两次搜索的最小间隔

PanSou 会去搜 TG 频道和第三方插件，连续请求容易被限流。建议 800~1500。

搜索结果缓存时长

同一个关键词在此时长内不重复请求。0 = 不缓存。建议 720（12 小时）。

✓ 已保存并生效

两种触发方式：① 采集时自动（同步跑完、新条目入库后自动补；补到地址的条目会再生成一次静态页，否则前台看不到下载按钮）；② 后台手动（「试搜」只搜索不写库，「立即补地址」给还没下载地址的条目补）。
匹配算法：similar_text 相似度 + 包含关系加分（资源标题常带「1080P / 全集 / 更新至xx」）+ 年份命中加分；中文标题搜不到高分时会自动用 original_title 再搜一次。
不污染手工数据：写入时按网盘标签去重，某网盘已有链接就保留站长手工填的那条。
表：pan_search_cache（搜索缓存）、pan_pending（待确认队列），首次使用时自动 CREATE TABLE；数据库用户无 CREATE 权限时导入 sql/migrate_site_seo.sql。
自检：check.php 第 10 组会真实请求一次 /api/health 并回报频道数 / 插件数。
