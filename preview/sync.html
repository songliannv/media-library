采集参数

保存到数据库 app_settings，立即生效；后台网页与每小时计划任务共用这一套参数。

每个源、每次最多入库多少条

把「一次同步」限制在可控范围内：既遵守各源配额，也避免站点被灌满。TMDB 单次上限 20 条/页，RAWG 单页上限 40，所以填 20~40 最合适。
条

单次同步的上游请求总数硬闸

超过这个数量的接口调用会被直接放弃，防止计划任务跑太久被网关掐断。RAWG 免费额度 20,000 次/月（约 27 次/小时），请留有余量。
次

TMDB 热门榜的时间窗口

对应官方 /trending/all/{day|week}。每小时跑一次建议用「今日」。

按什么口径取内容

最热 = TMDB trending / RAWG -added / Bangumi 当日在播；最多人看 = TMDB popular 榜 / RAWG -rating / Bangumi 排行榜。

同名同年（跨数据源）是否也跳过

例如同一部片在 TMDB 与 Bangumi 都有：开启后只保留先采集到的那条，站内不会出现两遍。年份允许差 1 年。

两次自动同步的最小间隔

防止手动连点或计划任务撞车导致频繁请求上游。计划任务是每小时跑一次，这里填 55 即可（0 = 不限制）。
分钟

每小时计划任务（宝塔面板）

让服务器自己每小时采集一次；命令行脚本已加守卫，用网址访问会 404。
  1. 宝塔面板 → 左侧「计划任务」→ 添加任务
  2. 任务类型选「Shell 脚本」，任务名称如「媒资库-每小时采集」
  3. 执行周期选「N 小时 → 1 小时」（或「每小时」）
  4. 脚本内容填上面这条命令 → 保存；建议先点一次「执行」看输出是否正常
命令里的 php 建议用绝对路径（本机当前检测到：/www/server/php/72/bin/php），这样计划任务不会因为 PATH 不同而找不到命令。
脚本已做三重限制：① 与上次同步间隔不足 55 分钟会自己跳过（防重复触发）； ② 同一时刻只允许一个采集在跑（进程锁）；③ 单次请求总数不超过 8 次。
